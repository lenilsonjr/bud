REVIEW round 1
Reviewed: crew/BUD-69 against develop
What this does: Adds a `Vault` protocol with record types in BudKit, and a `MemoryVault` actor over `Tree` that can persist to the JSON file. `BudStore` now takes a `Vault`. It shows its local change at once, queues the vault write in order, and reloads the snapshot afterwards. It also reloads on `watch` callbacks and keeps `center` while its bud exists. `BudStore(fileURL:)` wraps a `MemoryVault` over the same file.
Ticket check:
- `protocol Vault` in pure Swift: met. It has every listed method, plus `setWhen` and `setDue`. `setState` takes an optional state, and `create` takes a `preferredPath`.
- `BudRecord` mirrors bud-ffi: partial, but acceptable. The fields and names match `core/bud-ffi/src/lib.rs`. `when`, `due` and `created` are `Date?` where Rust has `Option<String>`, so the later Rust adapter has to convert them.
- `Bud` and `Tree` gain the missing fields: met (`Bud.path`, `Tree.path(of:)`, `place(of:)`, `records()`, `Tree(records:)`, and an optional `id` on `add` and `capture`).
- `MemoryVault`: met.
- `BudStore` over a `Vault`: met. It loads the snapshot, keeps `center`, reloads on `watch`, and every mutation calls the vault and then reloads. `BudStore(fileURL:)` is kept.
- Existing tests and pictures keep passing, with toasts, undo and trash unchanged: met per CI. All five checks passed on the head, including the macOS, iOS and tvOS builds. I did not rerun the suite, as instructed.
- No App target, `project.yml`, `scripts/` or Rust changes: met. The diff touches only `Sources/BudKit`, `Tests/BudKitTests`, and the crew's `REPORT.md`.
Tests: `VaultTests` has 12 Linux tests covering the seed round trip, create, edit, tick, move, trash, restore, branch trash, delete forever, empty trash, refused moves, the queries, `watch` and cancel, file persistence, and stable ids. `StoreVaultTests` has 10 SwiftUI-only tests covering load, add, capture, edit, tick, pin, move and its undo, trash, restore and undo, delete forever, empty trash, a `watch` reload, the center staying put, and the file store. Per the builder, `swift test` ran 100 tests with 0 failures. CI compiled `BudStore` and `StoreVaultTests` and was green. The box gate was not run by me, because the CI result was given. The hard rules hold: no personal data, the SwiftUI file stays behind `#if canImport(SwiftUI)`, and there are no literal colours.
Findings:
1. Sources/BudKit/BudStore.swift:~108 (`write`) and MemoryVault.swift:173 (`save`) nit: persistence to `buds.json` is now asynchronous, through a queued task and then the actor. Before, `save()` ran synchronously inside each mutation. A change made just before the app is killed or suspended could be lost where it was not before. Unsure whether the apps care; consider noting it for the RustVault ticket.
2. Sources/BudKit/BudStore.swift:~96 (`settle`) nit: `settle()` awaits only the last queued write. It does not await the initial `reload()` and `startWatching()` task started in `init`. A test or caller that settles straight after construction could race with the first load or the watch registration. CI was green, so this looks benign in the current tests.
3. Sources/BudKit/BudStore.swift (`trash`, undo path) nit: undo now calls `restore(id)` on the local tree. It used to restore the captured branch. If the Trash is emptied between the trash and the undo, undo is now a no-op, where before it brought the branch back. This is arguably better, but it is a small behaviour change.
4. Sources/BudKit/BudStore.swift (`write`) nit: a write the vault refuses is undone silently by the reload, and the success toast has already been shown. This is documented in the code and is fine for the memory vault.
verdict: approved
